# ADR 0006: Auto-merge content-only Daily Ingest PRs

Content-only Daily Ingest PRs (every changed path a `.md` under `concepts/` or `drafts/`) enable GitHub's squash auto-merge via `gh pr merge --auto --squash`, landing as soon as the `checks` status turns green. The change set is derived from the created commit's file list and gated against the content allow-list (paths under `concepts/` or `drafts/` ending in `.md`), so any future top-level path is conservatively non-content. A PR touching any non-content or non-`.md` path skips auto-merge and receives a comment listing the offending paths for manual review. Auto-merge is best-effort: a `gh pr merge` failure logs a warning and exits 0, so a transient API failure never turns a successful run red.

The alternative of a separate event-driven workflow (listening for `pull_request` events on `daily-ingest/*` and auto-merging there) was rejected: it duplicates the allow-list logic across two places, adds a second workflow to maintain, and its token would need separate permissions. An explicit approval/review step was rejected because the pipeline's audit subagent is the intended quality gate — for content-only changes there is no code to review, and a human click adds latency with no signal. A per-PR/per-run opt-out label was rejected as speculative complexity: no consumer exists today, the Daily Ingest cadence (20:15 UTC) makes a bot-driven revert cheap, and content-only changes are inherently low-risk. Non-Daily-Ingest PRs are unaffected — the logic lives in `scripts/daily-ingest.sh`, which the scheduled and `workflow_dispatch` runs both call identically, and `--dry-run` still never creates a PR or branch.
