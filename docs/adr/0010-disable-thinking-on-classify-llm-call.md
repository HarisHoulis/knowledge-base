# ADR-0010: Disable thinking and raise the cap on the classification LLM call

The classification/summarize request now sends `{"thinking": {"type": "disabled"}}` and `max_tokens: 4000` (raised from 2000), written inline in `classify_summarize`, and the audit cap is raised from 1000 to 2000. This extends ADR-0009 to the second call site. With thinking enabled by default at high effort, the model's hidden `reasoning_tokens` are drawn from the same `max_tokens` budget as the visible JSON, so long sources starved the answer — `finish_reason='length'` with `reasoning_tokens` near the cap — and the pipeline filed daily "LLM response failures" (empty or truncated content). #654 fixed the audit call only and deferred the classification call; this closes that gap. Disabling thinking returns the full budget to the answer and makes `temperature` effective again (it has no effect while thinking is on). The cost is explicit: summarization forfeits model chain-of-thought — a trade accepted because the audit loop, not generation-side reasoning, is the reliability gate. `response_format: {"type": "json_object"}` is unchanged; per DeepSeek's JSON-mode recipe the system prompt now includes the literal word `json` and a worked example object.
