# Coding Agents Don't Scale Themselves. Neither Do Your Teams.

Patrick Debois argues that the real challenge with AI coding agents is not the technology but organizational readiness. He draws a parallel to early skepticism about continuous delivery in 2009, noting that the current resistance to 'dark factory' autonomous development signals teams are not yet prepared, not that the technology is impossible. Optimizing agents with loops, harnesses, and evaluation is valuable but will soon become commoditized by frontier labs, so the true differentiator is how teams and organizations adapt their workflows and culture (Debois, 2026).

As developers shift from writing code to acting as conductors or orchestrators of agents, many feel a loss of technical identity. Debois observed that building tooling and harnesses for agents creates a new technical path that re-engages engineers who initially resisted prompt-centric work. Skeptical team members can be particularly effective when redirected to improve the agent's context and harness rather than merely complaining about output quality. This turns resistance into a force for improving the system.

The key mentality shift is to stop fixing the code the agent produces and instead improve the system that generates it—building the thing that builds the thing. This abstraction of context, harnesses, and evaluation becomes the core engineering work. Debois emphasizes that this organizational and technical focus on the meta-level is what will scale agent adoption, not the agents themselves.

- Agent technology will commoditize; organizational readiness is the real differentiator.
- Developers should shift from fixing agent output to improving the agent system (context, harnesses, tooling).
- Skeptical engineers can be engaged to build better context and harnesses, turning resistance into improvement.
- Adopting coding agents changes team dynamics and requires a new technical identity beyond prompt writing.
