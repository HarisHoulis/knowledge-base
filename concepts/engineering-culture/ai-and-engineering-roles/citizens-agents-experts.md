# Citizens Build, Agents Execute, Experts Govern

The article highlights a growing disconnect between non-engineers who can now build software over a weekend using AI and the engineering teams expected to deliver enterprise-grade systems. The author argues that writing software is not the same as software engineering; production environments demand data protection, resilience, maintainability, auditability, scalability, and proactive monitoring—concerns absent from demos. As Laycock writes, "Organisations don’t run on code. They run on trust" (source).

Laycock proposes the model "Citizens build, agents execute, experts govern." AI empowers a wider population to express ideas as software, and agents increasingly handle code generation, refactoring, testing, and bug fixes. However, this does not diminish the need for experienced engineers; instead, it makes them more leveraged. Their role shifts from hand-building every feature to designing guardrails, architecture, security, compliance, and feedback loops that allow safe, scalable creativity. At FOSE, discussions focused less on coding and more on design, governance, and judgment—humans deciding "what good looked like" while agents worked overnight (source).

- AI lets citizens create real software, but that differs from deploying and maintaining trusted enterprise production systems.
- Scarcity is shifting from coding ability to engineering judgment: knowing what good looks like and whether something is safe to trust.
- Agents execute code generation and iteration, while experts govern via design, trade-offs, and acceptance criteria.
- Experienced engineers become more leveraged by creating environments where many features can be built safely by humans and agents.
- The future model is citizens building, agents executing, and experts governing—not everyone becoming a software engineer.
