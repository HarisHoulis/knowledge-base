# Coding Agents Don't Scale Themselves. Neither Do Your Teams.

Patrick Debois compares the current resistance to autonomous coding agents (the 'dark factory') to the skepticism around continuous delivery in 2009. He argues that the technology itself will eventually become commoditized, so the real differentiator for organizations will be how they adapt their team dynamics, platform, and organizational structure. The frequent response that 'it won't work here' signals that teams are not yet ready organizationally, not that the technology is impossible.

Debois observes that the common narrative—developers becoming conductors or orchestrators of agents—can create identity friction, as many engineers did not sign up for prompt writing or spec refinement. However, when teams start building harnesses, loops, and tooling for agents, a new technical path opens that reignites engineering enthusiasm. He suggests that skeptical team members should be recruited to improve the agent's context and harness, channeling their criticism into making the system better.

The key mentality shift is to stop fixing the code that agents produce and instead improve the system that builds the code. This echoes the idea of building the thing that builds the thing. For organizations, this means investing in context engineering, tooling, and the developer experience around agents rather than treating agent output as a one-off task.

- Coding agent technology will become a commodity; organizational readiness is the true differentiator.
- Developers may resist the 'orchestrator' role, but building agent tooling/harnesses restores engineering craft and identity.
- Engage skeptical team members to improve agent context and harness, turning their criticism into actionable improvements.
- Shift from fixing agent-produced code to improving the broader system that generates that code.
- Adopting autonomous agents changes collaboration dynamics, requiring deliberate team and platform evolution.
