# Long Vol: What is Volatility?

Kent Beck frames software development as a domain of irreducible uncertainty. He lists basic assumptions: we don't know how users will perceive delivered features, how they'll talk about them in their communities, or how much implementation will cost—even if today's answer is 'less,' the magnitude remains unknown (Kent Beck, 2026).

By naming these unknowns as volatility, Beck connects product and engineering decisions to the financial idea of long volatility: outcomes are uncertain and can swing widely, so strategies should account for surprise rather than assume predictable returns. The post is a short framing piece, setting up the concept rather than resolving it.

The takeaway is epistemic humility in planning: treat user perception, community response, and cost as genuinely unknown variables, not estimates to be nailed down.

- User perception of delivered features is fundamentally unpredictable.
- Community discussion and word-of-mouth effects are unknown in advance.
- Implementation cost remains uncertain even when trending lower.
- Framing these unknowns as volatility suggests planning for surprise rather than false precision.
