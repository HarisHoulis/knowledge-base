# Stop being skeptical about AI for development with Charity Majors

In this podcast episode, Charity Majors, CTO of Honeycomb, explains why she shifted from AI skepticism to seeing AI as a generational change in software engineering. She notes that in 2025 skepticism was rational, but after November 2025, with Opus 4.5 and the Claude Code harness, AI became comparable to cloud computing in 2010 (Orosz, 2026). Majors argues that engineers must soon answer what it would take to ship code they have not read, as AI-generated code becomes more prevalent.

Majors shares contrarian views: code review is overrated, DevOps has failed at connecting software engineers to production, and non-deterministic systems require more engineering discipline, especially in verification. She suggests AI may turn code from 'pets' to 'cattle' where faulty code is regenerated rather than maintained. She also advises engineering directors to gain AI experience, warns that the window for moving back to IC work is closing, and asks both AI enthusiasts and skeptics to tell the whole story, acknowledging both wins and costs.

- AI skepticism in 2025 was rational, but by 2026 AI is a generational change similar to cloud in 2010.
- The coding harness (e.g., Claude Code) has made a bigger difference than the model itself.
- Code review is overrated; humans should focus on conversations and deciding what to build, not reading code for bugs.
- DevOps has failed to make software engineers understand their code in production.
- AI-generated code demands more investment in validation: tests, evals, and conformance testing.
- Engineering leaders should get AI experience or consider returning to IC work for more agency.
