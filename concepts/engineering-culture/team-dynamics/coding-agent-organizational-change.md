# Coding Agents Don't Scale Themselves. Neither Do Your Teams.

Patrick Debois argues that the real challenge with coding agents is not technical but organizational, comparing the current resistance to the early skepticism around continuous delivery in 2009. He observes that many teams say a "dark factory" of autonomous software development "will not work here," but interprets this as a signal that they are simply not ready—not that the technology is incapable. He predicts the agent harnesses and loops being discussed at conferences will eventually become commoditized, so they will not be a differentiator for any single organization.

Adopting coding agents changes team dynamics significantly. While the common narrative is that developers become "conductors" or "orchestrators" of agents, Debois notes that many engineers resist spending their time writing prompts and specifications. However, once teams start building tooling, harnesses, and context for agents, a new technical path opens up that reignites engineering interest. He advises leveraging skeptical or resistant team members to improve the context and harness, turning their criticism into a force for better agent outputs.

The key mentality shift is to stop fixing the code the agent produces and instead improve the system that produces it. Debois echoes Swyx's earlier idea: "stop building the thing, but build the thing that builds the thing." This abstraction—from code to the context, harness, and tooling around the agent—is where engineering craft can now be applied, and it is essential for scaling agents across teams and organizations.

- Coding agents will become commoditized; the differentiator is organizational readiness, not the agent technology itself.
- Teams must adapt to new dynamics where developers shift from writing code to building tooling, context, and harnesses for agents.
- Skeptical or resistant developers can be valuable in improving agent context and harness quality.
- The core mentality shift is to improve the system that builds the code, not to manually fix agent-generated code.
- Borrowing Swyx's framing, the focus should be on 'building the thing that builds the thing.'
