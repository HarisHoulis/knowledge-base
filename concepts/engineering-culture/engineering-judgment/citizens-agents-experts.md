# Citizens Build, Agents Execute, Experts Govern

Rachel Laycock observes a widening gap between what non-technical people think software engineering is and what experienced engineers know it to be. She notes that executives and hobbyists can now build apps over a weekend using AI, leading them to question why engineering teams aren't ten times faster. However, building software is not the same as engineering software for production. The moment an application becomes business-critical, questions about security, resilience, operability, compliance, and scalability arise—questions that don't appear in demos or weekend builds unless an experienced engineer is present (Laycock, n.d.).

Laycock argues that experienced engineers become more important, not less, because they provide judgment: knowing what good looks like, understanding risks, and deciding whether something that works can be trusted in production. She recounts discussions at FOSE where coders focused less on writing code and more on design, architecture, governance, and judgment. One team designed a specification, let agents work overnight, and reviewed results in the morning—highlighting that humans decide what good looks like and make trade-offs (Laycock, n.d.).

The author introduces the phrase 'Citizens build, Agents execute, Experts govern' to describe where value is moving. Citizens (non-engineers) express ideas, agents execute code generation and refactoring, and experts provide governance, architecture, security, and operability. Rather than making engineers obsolete, this shifts their role to creating guardrails and feedback loops so others can build safely at scale. Laycock concludes that both executives and engineers are right: anyone can build software, but somebody must live with it in production (Laycock, n.d.).

- Building a weekend app is vastly different from shipping enterprise-grade software that runs in production and must be trusted.
- Engineering judgment—knowing what good looks like, understanding risks, and assessing production-readiness—becomes more valuable as AI makes code generation easier.
- The role of experienced engineers shifts from building features to designing systems, guardrails, and practices that allow safe, scaled creation.
- The future is not everyone becoming an engineer, but citizens building, agents executing, and experts governing.
- Organizations don't run on code; they run on trust.
