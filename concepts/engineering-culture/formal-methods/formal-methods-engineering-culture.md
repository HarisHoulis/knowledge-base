# Formal methods with Hillel Wayne

In this episode of The Pragmatic Engineer podcast, host Gergely Orosz interviews formal methods consultant and author Hillel Wayne about the role of formal methods in modern software engineering. Wayne's Crossover Project, which interviewed about 20 traditional and software engineers, leads him to conclude that software engineering earns the title of 'engineer' due to its rigor, and that version control is a unique and sophisticated tool that traditional engineering fields lack (Orosz, 2026).

- Software engineering is a legitimate engineering discipline, with version control being a unique advantage over traditional fields.
- TLA+ is a formal specification language that caught a bug at Amazon requiring a 35-step error trace, undetectable by testing and review.
- Formal methods are niche because real-world specifications are complex, so property-based testing is a more practical lightweight approach for most teams.
- AI will not make formal verification mainstream, but it will increase usage from roughly 0.1% to 0.3%, and those who succeed with AI-generated specs are typically formal methods experts.
- Software engineering could learn from traditional engineering by documenting fundamental knowledge (e.g., The First Snap-Fit Handbook), as there is not even a book on API versioning.
