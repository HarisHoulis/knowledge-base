# Jam-Oriented Programming: Bringing Improvised Jazz to Engineering

Lu Wilson presents "jam-oriented programming," a deliberately jokey name for a serious style of software development that borrows the practices and mentality of an informal music jam session. In a typical jam, no one is in charge and anyone can make any sound at any time; in jam-oriented programming, anyone can add, edit, or delete code without permission (GOTO Copenhagen 2026).

The talk traces a progression from "one head" (individual development, including a project Wilson calls the "crappy fiddle" from five years earlier) through "many heads" (collaborative work) to "too many heads" (open, permissionless contribution). The concrete artifact is Nudel.cc, a music-making tool built under these conditions, where everyone is admin, nothing is certain, and anything can happen (GOTO Copenhagen 2026).

Wilson argues that this apparent chaos is surprisingly successful: entire music-making tools appeared overnight out of the multi-headed process, and the work even produced a published academic paper. The talk closes with the idea of letting code die, framing impermanence and open contribution as features rather than failures, and asks what this says about how developers collaborate (GOTO Copenhagen 2026).

- Jam-oriented programming applies jam-session norms to code: no one in charge, anyone can contribute at any time
- Everyone is admin and nothing is certain—permissionless editing is the default, not an exception
- The approach produced working tools like Nudel.cc and a published academic paper despite (or because of) the chaos
- The talk progresses from solo work (one head) to collaboration (many heads) to open permissionless contribution (too many heads)
- "Let code die" frames impermanence as part of the collaborative model
