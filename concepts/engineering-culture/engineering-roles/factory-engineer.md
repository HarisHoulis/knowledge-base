# What the devil is a Factory Engineer?!

Kent C. Dodds examines a memo by Zach Lloyd of Warp, which argues software engineering is shifting from product engineering to factory engineering. In Lloyd's view, engineers no longer write code or create products directly; instead they build cloud-based software factories—systems in which AI agents automatically handle triage, feature detection, implementation, verification, and monitoring. Success would be measured by the percentage of changes delivered automatically and at what cost, rather than by the number of features a human engineer delivers by hand. Dodds summarizes this idea but pushes back: an engineer's work in the future is to create a system where agents can operate, while retaining deep product understanding. He says the real concern is building the right thing, not maximizing automation percentage. He allows that if roles are split between factory builders and product owners, the factory metric can be useful for the factory side, but it should not define overall engineering success.

- Zach Lloyd/Warp predicts a move from AI autocomplete to interactive coding agents and then to automated development, in which engineers build software factories rather than write code.
- In the factory model, engineers create an internal system enabling AI agents to deliver product changes end-to-end: triage, implementation, verification, and monitoring.
- Success according to the factory approach would be measured by the percentage of all changes delivered automatically and their cost, not feature throughput.
- Kent Dodds agrees engineers will increasingly build systems that AI agents work within, but cautions that product insight and building the right thing matter more than automation statistics.
