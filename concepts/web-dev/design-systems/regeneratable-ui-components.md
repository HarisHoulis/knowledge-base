# From Reusable to Regeneratable: Rethinking the Shared UI Component Library

The article argues that AI-driven regeneration has changed the economics of code reuse for UI development. According to Curtis, a model pointed at a solid design system can produce most standard UI on demand, which makes paying to keep a canonical component package alive much harder to justify than it used to be (Curtis).

Instead of centralizing reusable components, Curtis recommends keeping the design system itself central—specifically the tokens, guidelines, and tests. These elements are what actually buy consistency across generated UI (Curtis). They serve as the source of truth that a generative model can leverage to ensure on-demand output stays aligned with organizational standards (Curtis).

- Regeneration changes reuse economics: AI models can generate most standard UI on demand from a solid design system.
- Maintaining a canonical shared component package is increasingly hard to justify.
- Keep the design system, tokens, guidelines, and tests central—they provide consistency.
- The design system, not the component library, becomes the primary source of alignment.
