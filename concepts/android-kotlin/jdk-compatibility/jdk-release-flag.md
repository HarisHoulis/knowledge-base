# Kotlin's JDK release compatibility flag

The article recounts an Android crash caused by a `NoSuchMethodError` on `List.removeFirst()`. The code used Kotlin's `removeFirst()` extension function, but after building with JDK 21, the compiler resolved the call to the new member method on `java.util.List` (from JEP 431), because Kotlin prioritizes member functions over extensions. Even though `jvmTarget` was set to 1.8, that only controls the generated bytecode version, not the set of JDK APIs available to the compiler. Thus, the emitted bytecode referenced a JDK 21 method unavailable on older Android runtime versions.

- Setting `jvmTarget` does not restrict the JDK APIs you can call; it only sets the bytecode version.
- New JDK member functions can silently shadow Kotlin extension functions, causing runtime crashes on older platforms.
- Kotlin's `-Xjdk-release` flag works like `javac --release`, constraining the compiler to the specified JDK API surface.
- The flag is needed for Kotlin/JVM and multiplatform JVM targets; Android targets are already protected by using `android.jar` as the bootclasspath.
- Gradle DSL support for this flag is tracked in KT-49746.
