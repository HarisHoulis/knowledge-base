# MCP Still Matters Outside Full Terminal Agents

In a Hacker News comment responding to "MCP was always a bad idea?", Simon Willison argues the article "entirely misses the value that MCP brings today" (simonwillison.net). He concedes that when you run a full-blown terminal agent (Claude Code, Codex, Meta Muse, OpenClaw) with unfettered internet access, there is "almost no reason to use MCPs" — you can just let the agent call APIs directly.

The value appears when you want to operate something "less YOLO than that": MCP makes it much easier to provide that capability. Willison frames the mistake as concluding MCP is obsolete simply because full coding agents don't need it, which "misses out on all of the other things we might want to build."

- For terminal agents with open internet access, calling APIs directly makes MCP largely unnecessary.
- MCP's value is in non-YOLO setups where direct API access isn't desired.
- Judging MCP obsolete by full coding-agent needs overlooks other systems worth building.
