# The VibeSec Reckoning

Vibe coding has significantly accelerated software prototyping, but AI agents frequently recommend insecure configurations, introducing security problems. This article, authored by Martin Fowler, presents insights from Gautam Koul, Lucian Moss, Neil Drew-Lopez, and Daberechi Ruth Edeokoh, who encountered these challenges while building applications for Thoughtworks's global marketing efforts. Their experience highlights the tension between rapid AI-assisted development and the need for robust security practices.

To address this, the team recommends several practical measures. First, developers should write a security context file to guide AI agents toward secure decisions. Second, they must be cautious when accepting AI permission requests, as these can lead to unintended vulnerabilities. Third, creating a daily security intelligence feed keeps builders informed about emerging threats and recommended practices. Finally, providing secure-by-default harnesses and templates ensures that starting projects already incorporate security best practices, reducing the likelihood of insecure configurations.

- AI agents often recommend insecure configurations during vibe coding, creating security risks.
- Write a security context file to steer AI behavior toward secure outcomes.
- Exercise caution when approving AI permission requests to avoid exposing systems.
- Establish a daily security intelligence feed to stay current on threats and mitigations.
- Equip developers with secure-by-default harnesses and templates to embed security from the start.
