# From Coding to Knowledge Work Agents

Karan Vaidya, CTO of Composio, argues that coding agents became successful not only because models improved, but because the entire software development infrastructure was already built for agents: repositories, commit history, tests, CI/CD, reviews, linters, and rollback mechanisms provide the context, memory, and trust that agents need. Knowledge work in areas like support, finance, and sales lacks this supporting infrastructure, so the same agents that excel at coding operate blindly in those domains.

- Coding agents succeeded because the software engineering ecosystem already had centralization, history, and safety rails.
- Knowledge work today is fragmented across Salesforce, Notion, Gmail, Slack, and Zendesk, with no single source of truth.
- Agents for knowledge work need new infrastructure primitives, starting with centralization of apps, connections, logins, and access rights.
- A recording layer or history is essential so agents can remember what worked, what didn't, and so humans can audit agent actions.
