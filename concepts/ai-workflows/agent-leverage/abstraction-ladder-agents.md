# How to Increase Your Leverage with Agents

In this video, Kent C. Dodds argues that AI coding agents are not replacing developers but moving them up the abstraction ladder. He compares the current shift to past transitions from assembly to Fortran/COBOL, then to Java/C#, and on to higher-level languages like Python and JavaScript. With agents, developers increasingly work with natural language rather than syntax, but they still work on the system itself, a point he attributes to Uncle Bob ([source](https://www.youtube.com/watch?v=v2gdCCc3N-g)). To increase leverage, Dodds advises developers to look at what they are doing manually today and delegate those tasks to agents, expecting the trend to continue: what we do ourselves now, agents will do for us in the future. He acknowledges that some high-level tasks like taste, judgment, and system design review may remain human, but agents can handle supporting high-leverage tasks. As an example, he describes using his phone to dictate an architecture improvement idea to an agent while at a theme park, which then can orchestrate sub-agents to work on separate aspects ([Kent C. Dodds, 2026](https://www.youtube.com/watch?v=v2gdCCc3N-g)).

- Agents move developers up the abstraction ladder rather than replacing them; historically, each new abstraction level has created higher-leverage human work.
- To stay effective, identify the busy work you're doing right now and get an agent to do it; your current manual tasks are likely future agent tasks.
- High-level judgment, taste, and architecture review still require humans, but agents can be used to make those tasks easier.
- A practical pattern: give an agent a health assessment or architecture idea, and let it orchestrate multiple sub-agents in separate environments.
