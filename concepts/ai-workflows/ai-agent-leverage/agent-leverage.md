# How to increase your leverage with agents

Kent C. Dodds argues that AI agents are not replacing developers but shifting them up the abstraction ladder. He observes that the tasks he outsources to agents today were tasks he did himself months ago, and expects this trend to continue, with agents eventually handling what he does now, freeing him for higher-leverage work. He cites Uncle Bob's observation that software development has continuously moved up from assembly language to high-level languages, and now to natural language as the interface for coding agents.

Dodds advises developers to identify the 'busy work' they are currently doing and find ways to have agents automate it, while recognizing that tasks requiring taste, judgment, system design, and architecture remain areas where humans add unique value. He shares an example of using an agent to perform a health assessment of a system architecture, breaking the task into subagents for focused analysis.

- Agents are not taking jobs; they take tasks, allowing developers to move up a layer of abstraction.
- The trend: what agents do today were manual tasks months ago; what developers do today, agents will do in the future.
- Focus on automating current busy work with agents, freeing time for higher-leverage activities.
- Human skills like taste, judgment, system design, and architecture remain valuable and harder to automate.
- Practical example: using an agent (e.g., Fable 5 or Opus 5) to run a system health assessment, with subagents for each concern.
