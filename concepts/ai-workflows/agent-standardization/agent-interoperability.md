# Every Company Is Building Agents That Can't Work Together

Justin Schroeder observes that despite conventional advice to expose business capabilities via MCP servers and drive them with Markdown-based skills or agent files, companies keep building bespoke agents instead. He argues this is not simply a mistake but reflects real market logic, and that the resulting fragmentation means agents built by different companies cannot interoperate.

The first driver is integration: a business is fundamentally its processes—warranty claims, scheduling field teams, permits, financial aid, account disputes—and these must be handled properly, not treated as secondary. Handing core processes to a general-purpose model like a generic chatbot is too risky; businesses want control, reproducible and reliable behavior over time, and their own voice and tone rather than fully generic tools.

The second driver is confidence in the agent's actions. An agent that can do everything can do anything, which Schroeder frames as an unacceptable responsibility. Agents need to be narrowly scoped so they cannot, for example, create new accounts on a warranty portal or fire off several emails at once simply because they hold broad tools. The talk sets up agent standardization as the response to this tension between bespoke, controlled agents and the need for them to work together.

- Companies keep building custom agents even when advised to just expose MCP servers plus Markdown skill files, suggesting market logic rather than error.
- Business value is rooted in processes, so AI must integrate deeply with core operations rather than sit in generic tools.
- Businesses prioritize control, reproducibility, and brand voice over delegating critical processes to a general model.
- Broad tool access is a liability: agents must be narrowly scoped so they cannot take unintended actions.
- Lack of standardization leaves independently built agents unable to interoperate.
