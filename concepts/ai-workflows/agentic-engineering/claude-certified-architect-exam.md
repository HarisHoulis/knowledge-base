# Anthropic's CCA Exam as a Field-Guide for Agentic Engineering — Frank Coyle, UC Berkeley

Frank Coyle, a computer science educator at UC Berkeley, presents the Claude Certified Architect (CCA) exam as an essential roadmap for careers in agentic AI. The exam, released in March 2026, is scenario-based, timed, proctored, and available to individuals for $99, with a six-month retake window. It covers five domains: agentic architecture (27%), Claude Code configuration and workflow (20%), prompt engineering with structured output, tool design and Model Context Protocol (MCP) integration, and context management with reliability. The exam is built around six production scenarios, of which four are randomly selected for each test-taker (Coyle, 2026).

Coyle emphasizes that understanding anti-patterns is key to succeeding in agentic engineering, drawing an analogy to the design patterns movement of the 1990s. He walks through the production scenarios, including a customer support resolution agent, code generation, multi-agent research systems, developer productivity with code, continuous integration, and structured data extraction. He highlights the importance of agentic loops, stop reasons in Claude Code, orchestrator patterns like hub-and-spoke, and subtask isolation to avoid synchronization issues—echoing lessons from multi-threaded programming. He also cites practitioners like Boris Cherney and Peter Steinberger, who describe their roles as 'writing loops' or no longer coding directly, reinforcing the shift toward designing agent workflows (Coyle, 2026).

- The CCA exam is a practical, scenario-based certification covering five core domains of agentic engineering, with agentic architecture weighted at 27%.
- Understanding anti-patterns—what not to do—is critical for both passing the exam and building reliable agents.
- Production scenarios include support resolution, code generation, multi-agent research, developer productivity, CI, and data extraction; each tests distinct architectural and reliability concepts.
- Agent design should emphasize loop control, task isolation, and orchestrator patterns (e.g., hub-and-spoke) to avoid shared-state and synchronization problems.
