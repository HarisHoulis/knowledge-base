# Fable and the End of the Free Lunch: Rethinking Model Choice

Drew Breunig observes that before Fable, it felt pointless to invest heavily in coding harnesses or context strategies, because new models would arrive at the same price and effectively mask those inefficiencies. Fable, however, is powerful but significantly more expensive, while models like Opus, 5.6, K3, and GLM are 'good enough' for most coding tasks. This creates a strategic shift: teams can no longer assume the next model will paper over workflow flaws; instead, they must deliberately decide which tasks justify a premium model and which can be handled by cheaper alternatives.

- Before Fable, teams could rely on newer, cheaper models to compensate for suboptimal coding harnesses or context strategies.
- Fable is excellent but high-priced, making it unsuitable for every coding task.
- Cheaper models like Opus, 5.6, K3, and GLM handle the majority of coding needs sufficiently.
- The new reality requires conscious routing of work based on model cost and capability.
