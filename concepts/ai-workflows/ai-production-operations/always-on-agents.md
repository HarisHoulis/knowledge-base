# Always-on agents run production without the on-call tax

In this talk, Justin Smith from Resolve AI argues that while AI has accelerated code production, it has not reduced the operational burden. Citing a survey, he notes that 70% of engineer time is spent not on writing code but on running it—maintaining platforms, scaling infrastructure, debugging incidents, and being on call. AI-driven development is making this worse by generating larger PRs and faster shipping, increasing production issues and complexity.

Smith advocates using AI inside production to manage the complexity AI itself creates. Resolve's hypothesis is that increased coding velocity will produce more incidents, so they built 'always-on agents' such as an on-call agent that triages alerts and performs root cause investigation. This represents a shift toward 'full-stack AI,' where models are embedded in domain-specific contexts and operational workflows, not just generating code.

The broader point is that organizations must use AI operationally to keep balance across teams and systems. As token costs rise and companies clamp down on AI usage, the differentiator becomes the context around models and their ability to act within a specific domain. This is true today as systems have always been complex, but AI can help manage that complexity if applied correctly.

- 70% of engineering time goes to production operations, not development.
- AI-accelerated coding increases PR size and incident volume, straining existing processes.
- Always-on AI agents (e.g., on-call agent) can triage alerts and investigate root causes.
- Effective AI requires full-stack integration: models plus domain context and operational tools.
