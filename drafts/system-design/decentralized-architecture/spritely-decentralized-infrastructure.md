# Spritely: Infrastructure for the Future of the Internet

Christine Lemmer-Webber and David Thompson explain how Spritely's architecture solves core decentralization challenges [source]. They discuss capability-based access control with Goblins, actor-model communication via OCapN, and petname systems [source].

The presentation covers how Spritely leverages Scheme, WebAssembly (Hoot), and local-first CRDTs to build secure, peer-to-peer applications without central servers [source]. Together, these components aim to provide infrastructure for decentralized applications on the internet [source].

- Spritely combines capability-based access control (Goblins), actor-model communication (OCapN), and petname systems.
- It addresses core decentralization challenges for peer-to-peer applications without central servers.
- The architecture uses Scheme, WebAssembly (Hoot), and local-first CRDTs.
