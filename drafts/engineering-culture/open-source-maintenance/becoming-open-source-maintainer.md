# Becoming an Open Source Project Maintainer

To become an open source maintainer, the easiest path is to create your own project, but often the greater need is improving an existing project (https://kentcdodds.com/blog/becoming-an-open-source-project-maintainer). Kent C. Dodds advises contributing best to something you use regularly, otherwise you will lose motivation quickly (https://kentcdodds.com/blog/becoming-an-open-source-project-maintainer).

Dodds describes his path with `angular-formly`: he needed a forms library, filed an issue, made pull requests, helped in issues, and reviewed pull requests. Eventually the maintainer asked if he wanted commit and publish access, which made sense because he was doing more for the project than the maintainer was at the time (https://kentcdodds.com/blog/becoming-an-open-source-project-maintainer).

The key takeaway is to act like a project maintainer: help with issues, make pull requests, help with documentation, answer questions, make tutorials, and review pull requests. There is no need to get permission to do those things; just start doing them as much as you are willing and able (https://kentcdodds.com/blog/becoming-an-open-source-project-maintainer). Many benefits of open source come even if you are not the project maintainer, and projects often need new maintainers.

Not all maintainers are the same; some do not want to relinquish control. If you have an issue with how a project is maintained and the maintainers will not let you help in the way you want, you can fork the project, with `lodash` as a famous example (https://kentcdodds.com/blog/becoming-an-open-source-project-maintainer). Open source lets you do good work without anyone's permission, so long as you follow the project code of conduct and respect the maintainers; if that does not work out, your BATNA is to fork the project, while being aware of the project license (https://kentcdodds.com/blog/becoming-an-open-source-project-maintainer).

- Contribute to projects you actually use regularly, or motivation will fade.
- Act like a maintainer: help with issues, pull requests, documentation, questions, tutorials, and reviews.
- Maintainership often emerges from consistent contribution; `angular-formly`'s maintainer offered Dodds commit and publish access after he contributed heavily.
- Open source benefits can accrue even without formal maintainer status.
- If maintainers will not let you help as desired, forking is the BATNA; respect the code of conduct and license.
