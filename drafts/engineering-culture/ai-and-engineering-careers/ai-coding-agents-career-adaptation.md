# Feeling Sad About AI: Coming to Terms With Coding Agents

In a comment on Hacker News, Simon Willison responds to the essay "Feeling sad about AI" by describing the existential crisis many engineers hit when a coding agent completes in an hour, and well, work that would have taken them a week. He admits he went through that moment himself "a few years ago now" and came out the other side, framing the disheartening first reaction as a stage rather than an endpoint.

The way through, he argues, is accepting that translating an exact specification into decent code "isn't a unique skill any more." Once that is internalized, engineers can survey the larger set of problems they actually face and notice that "there is so much left" — and that existing skill and experience let them master the new tools, provide value, and "execute at a level far greater than anyone who is just getting started building software using agents without any of your depth."

He also pushes back on the expectation of stability. Anyone who doesn't want their profession to change at all will have a tough time, but that has always been true of software engineering: there has arguably never been stability in tools and languages "beyond about a five year time horizon." These changes are happening faster, but choosing software development as a passion has always meant opting into frequent radical change.

- Willison treats the dismay at capable coding agents as a passing existential phase he has already moved through.
- Translating an exact specification into decent code is no longer a unique skill, which frees engineers to attack the larger problem space that remains.
- Depth and experience let senior engineers use the new tools to outperform newcomers who build with agents without that depth.
- Software engineering has never offered tool and language stability beyond roughly a five-year horizon, so resisting change is the losing position.
