# How to Write a JavaScript Library

Kent C. Dodds describes creating and maintaining an open source JavaScript library as demanding, impatient, and time-consuming, comparing it to becoming a parent [source](https://kentcdodds.com/blog/how-to-write-a-javascript-library). He notes that small libraries can be easy to create and need little maintenance once done, but once a library grows beyond a few dozen lines, developers face challenges in developing, documenting, releasing, updating, and maintaining it. Despite those challenges, he says open sourcing a library is still worth it, whether it is a large framework or a simple utility.

The post promotes a free egghead.io series, “How to Write a JavaScript Library,” intended to help developers open source their work from the basics to current practices. Topics listed include setting up GitHub and npm, creating the library and adding dependencies, releasing to npm and GitHub, releasing new and beta versions, unit testing and code coverage, setting up continuous integration, automating the release process, linting, adding githooks, getting contributors, adding a transpiler for ES6 support, creating isomorphic/universal/portable JavaScript libraries, and documentation.

Dodds cautions that not all libraries need all of these practices, but many would benefit from them, and invites readers to start writing more open source JavaScript.

- Open sourcing a JavaScript library involves challenges across development, documentation, release, updates, and maintenance once it grows beyond a few dozen lines.
- The linked egghead.io series covers setup on GitHub and npm, dependencies, releases and beta versions, testing, coverage, CI, release automation, linting, githooks, contributors, ES6 transpilation, and universal JavaScript.
- Not every library needs the full set of practices, but many benefit from adopting them.
- The author encourages developers to publish more open source JavaScript.
