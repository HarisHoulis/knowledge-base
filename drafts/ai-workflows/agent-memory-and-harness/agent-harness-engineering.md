# Agent Memory and Harness Engineering: Building the Controllable Layer of AI Agents

Ignacio Martinez argues that while language models are the "frozen part of the reasoning," the controllable engineering surface for AI applications is the agent harness, especially the data layer. He frames the agent stack as five layers—application, data, model, infrastructure, and compute—and says that four of those layers are increasingly commoditized, leaving data as the area developers control most and where agent memory lives (Martinez, 2026).

The data layer is described as containing memory, knowledge, retrieval, encoding, search, and gateway/MCP concerns. Martinez says the agent harness sits closely with the data layer, and he outlines seven layers or structures that make up a minimal agent harness that can be connected to any model. The workshop portion of the session walks through building that harness (Martinez, 2026).

The talk also covers AI application shapes, definitions of what an agent is, and continual learning, with Oracle positioned as a vendor that can help teams develop agent harnesses and AI applications. Martinez notes prior work on agent memory, including a course with Andrew Ng, and uses a GitHub repo plus GitHub Codespaces so participants can run the workshop material (Martinez, 2026).

- LLMs are frozen; the agent harness is the controllable layer for engineering agent behavior.
- The five-layer agent stack is application, data, model, infrastructure, and compute; data is the most controllable and least commoditized layer.
- The data layer includes memory, knowledge, retrieval, encoding, search, and gateway/MCP components.
- A minimal agent harness can be built from seven layers/structures and connected to any model.
- The session links agent harnesses to continual learning and Oracle's positioning in AI application development.
