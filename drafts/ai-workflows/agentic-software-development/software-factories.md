# Software Engineering Is Becoming Factory Engineering — Zach Lloyd, Warp

Zach Lloyd, former chief engineer at Google (where he led Google Docs) and founder of Warp, argues that software engineering will become something more like "factory engineering": rather than writing code by hand, engineers will build and manage automated software factories. He notes he has not written a line of code in the last six months, and that his company Warp — originally a terminal, now an open-source development environment for agents — is increasingly focused on automating development rather than just interactive work.

Development, he says, has already moved from chat and AI autocompletion to an era of mostly interactive agents, and over the next six months to a year it will move much further into automation. The "software factory" he describes is a cycle that mirrors the software development life cycle: ideas come in, agents do the sorting, agents write a specification where the problem is complex, humans review the specification (the "blue squares" are the points of human intervention), agents handle implementation, a human and an agent review the code, agents run checks, people review the product, and then it ships and is monitored.

Part of Warp's motivation for open-sourcing was to create a "public factory." Warp has over 60,000 GitHub stars, several hundred contributors, and over 800,000 active developers. A site they built, build.warp.dev, shows all issues flowing through their system, what state they are in, which agents are working on them, and which contributors are on them — a proto-factory at scale that "doesn't work perfectly, but it works."

Lloyd's closing argument concerns the economics: building software is getting a lot cheaper, which makes cloning software trivial, and it is therefore hard to build a software business if software development is free and a competitor can clone.
