# Designing AI Agents as Knowledge Agents, Not Coding Agents

Ben Clavié (Mixedbread) argues that AI agents should be designed as knowledge agents rather than coding agents, because knowledge work is a superset that includes coding but is not limited to it (Clavié, AI Engineer, 2026). Early 2022 agents were mostly RAG plus an if-statement search to “talk to your PDF”; coding agents then became the dominant agentic form. Coding agents are a form of knowledge work, but agents were not yet knowledge workers and are now becoming them.

Knowledge work is defined as work whose main input is information—ambiguous and diffuse—and whose main output is something actionable: a judgment, decision, or finding. A topological definition is also offered: if you need search, it is a knowledge problem; if it is a knowledge problem, you need search. Examples include lawyers, academics, actuaries, software engineers, and researchers, and much of the service economy is knowledge work.

Agentic design has focused on the special case of coding and software engineering. Code is knowledge, but not all knowledge is code; code has durable cues such as identifiers, files, and paths, plus graspable surface features like keywords and method definitions. The implication is that general knowledge agents should be designed around knowledge-worker workflows rather than assuming coding-agent patterns.

- Design agents for knowledge work as knowledge agents, not just coding agents; coding is a subset of knowledge work.
- Knowledge work takes ambiguous information as input and produces actionable judgments or decisions as output.
- If you need search, it is a knowledge problem; if it is a knowledge problem, you need search.
- Agentic development has overfit to coding/software engineering, a special case with durable textual cues like identifiers and paths.
- Knowledge-work examples include legal, financial, medical, academic, actuarial, software engineering, and research work.
