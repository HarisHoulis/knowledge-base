# Rebuilding the web for agents — Liad Yosef, MCP Apps

Liad Yosef, co-creator and maintainer of the MCP Apps spec, describes MCP Apps as the spec behind chat-based apps from Claude, Copilot, GitHub, and other chat agents. It lets MCP servers send UI chunks into chats and was released a few months ago, with Claude as the first client and other clients following; it is widely supported across chat agents except Gemini, which Yosef says is coming [1].

MCP Apps addresses the “last mile” of interaction: as models become more autonomous, humans still need to choose a hotel, view a 3D model, or pick a seat. Embedding provider UI in chats preserves brand and identity for providers, gives users trust and familiarity—for example, seeing Booking.com—and gives hosts access to capabilities [1].

The “agentic web” is not a web of agents or today’s web, but a shift in how websites and browsers are viewed. Instead of opening tabs and learning each service’s UI to convey the same intent, interfaces can be broken into atoms that a personal assistant composes using user context—such as an upcoming anniversary or a preference for nature hotels—to book or buy on the user’s behalf [1].

Yosef notes the talk was built yesterday and may be outdated because the space is moving fast [1].

- MCP Apps is a spec that lets MCP servers inject interactive UI into chat agents, already used by Claude, Copilot, GitHub, and others.
- It solves the last-mile human interaction problem by keeping provider UI and brand inside chats while giving users familiarity and hosts new capabilities.
- The agentic web reframes websites as composable “atoms” that personal assistants can orchestrate instead of users visiting separate tabs and UIs.
- The shift benefits providers through brand/identity and users through trust/familiarity, and the space is evolving rapidly.
