# The Design-Code Roundtrip That Isn't — Jonathan Gordon, ReWeaver AI

Jonathan Gordon, founder of ReWeaver AI, defines the design-code roundtrip as a full loop between design and engineering in both directions without loss of fidelity and with persistent provenance—so there is no drift between design and code (AI Engineer, 2026). He argues today's design tools are impressive and interactive, but people have stopped looking at the generated code (AI Engineer, 2026). Drawing on 30+ years building design and coding tools, he says handoff was never a perfect science; outcomes diverged because engineering had technical constraints while design had visions like rebranding (AI Engineer, 2026).

With AI and LLMs, Gordon thought a single intelligence could understand design intent and write code, potentially closing the loop at the speed of inference (AI Engineer, 2026). He went all in on vibe coding from April 2025 and received a Cursor notice that he was in the top 0.1% of usage (AI Engineer, 2026). But while blindly accepting a wall of generated text, he noticed an innerHTML statement, recognized it as a security vulnerability, stopped the model, and asked it to revert (AI Engineer, 2026).

That experience pushed him to steer the model better and actually inspect the code, where he found issues (AI Engineer, 2026). He notes the industry started claiming the roundtrip had been solved, setting up his critique (AI Engineer, 2026).

- A true design-code roundtrip requires bidirectional fidelity and persistent provenance, with no drift between design and code.
- Current AI design tools can generate clickable, interactive designs, but generated code is often ignored.
- Past design-engineering handoff failed because engineering constraints and design visions diverged.
- LLMs raised the possibility of one intelligence handling design intent and code at inference speed.
- Gordon's innerHTML security scare led him to inspect and steer AI-generated code rather than vibe-code blindly.
